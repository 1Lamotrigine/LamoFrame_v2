Аудит проекта LamoFrame: ошибки и недочёты
Ничего в коде не менял — только анализ. Список сгруппирован по серьёзности; у каждого пункта указано место и суть. Ссылки на строки — по текущему состоянию файлов.

1. Критичное: безопасность и потеря данных

1.1. Гонка автосохранения теряет правки (потеря данных) — app/static/js/editor.js:648–672, app/static/js/state.js:1463–1470
saveNow() делает снимок документа в начале и сбрасывает dirty=false по завершении ответа. Если пользователь что-то меняет во время await renderStandalone(...) / await saveProject(...), эти изменения помечают документ грязным, но по приходу ответа setSaveState("saved") обнуляет флаг. Отложенный таймер сохранения затем видит dirty=false и молча выходит. Итог: часть правок не уходит на сервер и пропадает после перезагрузки.
1.2. Stored XSS через сохранённый HTML — app/builder/views.py:120–137, app/builder/views.py:232–240
API принимает от клиента произвольную строку html и сохраняет её в exported_html. Затем public_raw отдаёт её как text/html с того же origin. Валидации/санитайзинга на сервере нет. Пользователь может отправить HTML с <script> и получить выполнение кода на origin приложения при прямом открытии /p/<slug>/raw/. Ограничение через iframe sandbox в public_preview защищает родителя, но не прямой переход по ссылке «открыть отдельно» (public_preview.html:30). CSP нигде не выставлен.
1.3. Захардкоженные учётки администратора + автозасев в проде — docker-compose.yml:15, app/builder/management/commands/seed_demo.py:14–36, app/templates/registration/login.html:46–49
SEED_DEMO по умолчанию 1. Команда создаёт demo/demo12345 и admin/admin12345 (суперпользователь). Те же логины/пароли напечатаны на странице входа. Любой, кто дотянется до контейнера, входит админом.
1.4. Небезопасные прод-настройки — app/config/settings.py:10–17, app/config/settings.py:129–136, docker-compose.yml:13–14
Инсекьюрный SECRET_KEY по умолчанию, ALLOWED_HOSTS=*, нет SESSION_COOKIE_SECURE, CSRF_COOKIE_SECURE, SECURE_SSL_REDIRECT, HSTS и SECURE_PROXY_SSL_HEADER. Для контейнера за прокси это означает работу по HTTP и уязвимость к перехвату сессии.
1.5. WHITENOISE_USE_FINDERS=True в проде — app/config/settings.py:129–136
WhiteNoise будет искать статику в исходных каталогах, обходя collectstatic и манифест. Это может отдавать устаревшие/нехешированные файлы после пересборки и снижает предсказуемость кеша.
1.6. SQLite + 3 воркера gunicorn — Dockerfile:37, docker-compose.yml:16
Три процесса пишут в один SQLite-файл. При параллельных сохранениях вероятны database is locked и 500-е. Для многопользовательского режима это нерабочая конфигурация.
1.7. Нет защиты от конкурентных правок — app/builder/views.py:118–138
PUT /api/projects/<id>/ просто перезаписывает данные. Две вкладки/устройства затирают друг друга по принципу last-write-wins: ни updated_at, ни версии документа не проверяются.
1.8. Нет лимита на общий объём загрузок и обработка «бомб» — app/builder/views.py:16–17, 151–182
Ограничение только 2 МБ на файл, но количество файлов и суммарный объём не ограничены. Image.open().verify() не ловит DecompressionBombError (это не OSError/UnidentifiedImageError) — специально сжатая картинка даёт 500. EXIF-ориентация не применяется.
1.9. Удаление проекта не чистит файлы — app/builder/views.py:218–223
Удаляется только запись БД. Ассеты и превью остаются на диске; при пересоздании проектов мусор накапливается.
1.10. Медиа в проде отдаётся через django.views.static.serve — app/config/urls.py:15–21
Синхронная отдача из Python-процесса, без кеш-заголовков и отдачи через nginx/WhiteNoise. На реальной нагрузке это узкое место.


2. Логика редактора

2.1. Автосохранение срабатывает на транзиентные изменения — app/static/js/editor.js:211–216, app/static/js/state.js:506–511
update() при каждом pointermove помечает документ грязным и шлёт событие doc; обработчик вызывает scheduleSave() без проверки source === "transient". Перетаскивание/ресайз бесконечно перезапускают таймер, а при паузе сохраняют промежуточное состояние (иногда посреди drag).
2.2. Переключение страницы помечает проект изменённым и сохраняет его — app/static/js/state.js:971–993
switchPage() вызывает markDirty() и эмитит doc с источником "page", из-за чего срабатывает автосейв. Простое листание страниц меняет updated_at и гоняет полный снапшот + рендер.
2.3. Общий хедер/футер «переезжает» между страницами — app/static/js/state.js:813–828, 981
pinComponentFrames() при каждом switchPage переставляет общие компоненты по координатам текущей страницы. Поскольку компонент один на все страницы, его позиция в редакторе зависит от последней открытой страницы и сохраняется в таком виде.
2.4. Мультивыделение в разных фреймах: drag/resize считает от первого фрейма — app/static/js/canvas.js:450–476, 656–676
Для всех выделенных элементов берётся frameX/frameY первого элемента (interaction.frameId), хотя item.x — абсолютная координата. Элементы из других фреймов прыгают в неверные позиции. Мультивыбор跨 фреймов достигается маркизом и shift-кликом в слоях.
2.5. Панель свойств показывает локальные X/Y, а холст — абсолютные — app/static/js/panels.js:288–292, 621–648, 764–770, app/static/js/state.js:1149–1162
selectionBounds() возвращает координаты относительно фрейма, панель выводит их как X/Y, а оверлей и drag работают с абсолютными. В итоге цифры в панели не совпадают с визуальным положением; applyGeometry для одного элемента записывает локальные значения, для нескольких — абсолютные (несогласованная семантика).
2.6. Выравнивание/распределение кросс-фреймового выделения считается по локальным координатам — app/static/js/state.js:1241–1290
alignSelection/distributeSelection оперируют el.x/el.y без учёта смещения фреймов. Для элементов в разных фреймах выравнивание визуально неверное.
2.7. Colorpicker коммитит на каждый pointermove — app/static/js/colorpicker.js:85–108, 231–239, app/static/js/panels.js:124–137
Каждое движение мыши вызывает onPick → setStyleValue → commit, то есть pushHistory, полный serializeDoc, перерисовку канваса и постановку автосейва. Это и спам истории (undo/redo), и заметные лаги при перетаскивании цвета.
2.8. Панель свойств коммитит на каждый ввод и дублирует коммиты на change — app/static/js/panels.js:108–109, 511–574, 599–619
Нет сравнения с текущим значением: каждое нажатие клавиши в поле — отдельный commit; затем change при блюре коммитит то же значение ещё раз. На больших документах каждый символ перестраивает весь DOM канваса.
2.9. Новые фреймы в ручном режиме создаются шириной 1200 px — app/static/js/state.js:757–802, app/static/js/layers.js:76–80, 886–932
newFrame() и addFrame() используют дефолт w=1200 независимо от выбранного устройства. В ручном режиме на планшете/телефоне новый фрейм выходит далеко за пределы макета устройства.
2.10. Escape при переименовании фрейма/слоя всё равно коммитит старое имя — app/static/js/canvas.js:955–981, app/static/js/layers.js:245–263
Обработчик Escape возвращает старое значение и вызывает blur(), после чего blur-обработчик делает update...() — создаётся лишняя запись истории и автосейв, хотя пользователь отменил переименование. У страниц (pages.js) это сделано корректно.
2.11. Маркиз выделяет скрытые и заблокированные элементы — app/static/js/canvas.js:727–769, 423
Маркиз перебирает все элементы без фильтра hidden/locked. Скрытые элементы потом можно тащить (при drag фильтруется только locked).
2.12. Ресайз/перемещение повёрнутых элементов считается по неповёрнутому bbox — app/static/js/canvas.js:10–19, 656–676
elementAbsoluteRect() игнорирует rotation, поэтому для повёрнутых элементов ручки ресайза и снаппинг расходятся с визуальным положением.
2.13. Рисование фигуры создаёт две записи истории — app/static/js/canvas.js:404–407
addElement() делает один коммит, затем отдельный коммит на подгонку h. Одно действие — два шага undo.
2.14. Перемещение элемента может закинуть его в общий хедер/футер — app/static/js/canvas.js:481–502
maybeMoveElToAnotherFrame не исключает компонентные фреймы, поэтому контент страницы можно случайно перенести в общий компонент.
2.15. Вставка фреймов теряет роль компонента — app/static/js/state.js:1050–1090
pasteFrames удаляет role, так что скопированный хедер вставляется как обычный контентный фрейм. Может быть намеренно, но поведение неочевидно и не предупреждает.


3. Экспорт, превью и адаптив

3.1. Внутренние якоря (#...) не работают, а скрипт страниц перехватывает любой hash — app/static/js/render.js:939–961, app/static/js/blocks.js:243
Ссылки вида #features не имеют соответствующего id в экспорте. При этом PAGES_SCRIPT на hashchange ищет hash среди слагов страниц, не находит, сбрасывает на первую страницу и делает scrollTo(0,0). То есть клик по якорю уводит на главную и вверх.
3.2. Превью в дашборде и «Новом проекте» суммирует высоту всех страниц — app/static/js/dashboard.js:16–28, app/static/js/new_project.js:18–26
Высота iframe считается как сумма фреймов всех страниц, хотя рендерится и видна только первая. Получается огромный пустой блок и неверный масштаб миниатюры. Ширина для масштаба жёстко 1200, игнорируя doc.settings.width.
3.3. Не везде проставлен cache-busting — app/templates/dashboard.html:4, app/templates/new_project.html:4, app/templates/base.html:35
dashboard.css и new-project.css подключены без ?v=, iconsUrl — без версии. После пересборки Docker-образа браузер может держать старые стили/иконки, тогда как editor.css версионируется.
3.4. Компоненты для планшета/телефона не имеют fallback на desktop — app/static/js/render.js:347–358
docComponents() для не-desktop устройства читает только components.devices[device]. Для старых документов без device-компонентов хедер/футер на планшете/телефоне просто исчезает (в отличие от фреймов страниц, где fallback есть).
3.5. В авто-рефлоу пропадают все одиночные фигуры — app/static/js/render.js:788 (REFLOW_TABLET)
.sb-el-shape { display:none!important } скрывает декоративные фигуры и фигуры-заглушки (например, блок «Фото» в шаблоне «О нас»), если они не распознаны как карточка. Визуально секция теряет смысл.
3.6. Эвристика карточек хрупкая — app/static/js/render.js:485–529 (elementBlocks)
Карточкой считается фигура, содержащая не-фигуры и занимающая ≤55% площади фрейма. Любое нестандартное наложение, вложенные карточки или фигура-фон могут сгруппировать не то, из-за чего порядок и вложенность в рефлоу поедут.
3.7. Уровень заголовка не округляется — app/static/js/render.js:186
renderText подставляет h${level} без Math.round. Крафченные/старые данные с level: 1.5 дают невалидный тег h1.5.
3.8. ZIP без ZIP64 и без сжатия — app/static/js/zip.js:62–129
Экспорт >4 ГБ или >65535 файлов соберётся битым; всё хранится без сжатия, поэтому итоговый архив сильно больше, чем мог бы быть.
3.9. Нестабильные имена/порядок картинок в ZIP — app/static/js/bundle.js:139–155
Promise.all с мутацией общих used/files даёт недетерминированный порядок и суффиксы (image-2) от запуска к запуску. Экспорт одного и того же проекта может отличаться.
3.10. Некорректное декодирование не-base64 data URI — app/static/js/bundle.js:76–89
Бинарные данные проходят через decodeURIComponent + TextEncoder; байты >127 могут исказиться. Нужно percent-decode в байты.
3.11. Внешние картинки без CORS остаются внешними — app/static/js/bundle.js:152–154, app/static/js/render.js:1256–1258
При неудачном fetch картинка не инлайнится и не пакуется. ZIP не является полностью офлайн-сайтом, а сохранённый exported_html зависит от стороннего хоста.
3.12. Сохранение инлайнит все картинки в HTML и упирается в лимит 12 МБ — app/static/js/editor.js:661–666, app/builder/views.py:135–137
Предупреждение появляется только после 5 МБ, но жёсткий серверный лимит — 12 МБ. Проект с несколькими фото может вообще перестать сохраняться, при этом в редакторе данные остаются только в памяти.
3.13. Ложное «сервер недоступен» при экспорте — app/static/js/editor.js:687–699
Если saveNow({force:true}) вызван во время уже идущего сохранения, он возвращает false, и экспорт сообщает об ошибке сервера, хотя связь есть и сохранение просто в процессе.
3.14. Публичная страница без явной публикации/снятия с публикации — app/builder/views.py:226–240
Любой проект доступен по /p/<slug>/, как только у него есть exported_html. Отдельного флага «опубликовано» нет; знание слага = доступ. Для многопользовательского сервиса это риск утечки черновиков.


4. Производительность и UX

4.1. Полная перерисовка канваса на каждый коммит — app/static/js/canvas.js:96–102, app/static/js/state.js:520–530
Любой commit (ввод в поле, цвет, переименование) вызывает renderCanvas с полной заменой innerHTML и пересборкой кэша. На документах с сотнями элементов это заметно тормозит.
4.2. Панели и оверлей пересчитываются на каждом pointermove — app/static/js/editor.js:211–216, app/static/js/canvas.js:40–60
Транзиентный drag обновляет DOM элементов точечно, но оверлей/метаданные/кнопки пересчитываются целиком каждый кадр. На больших макетах — лишняя нагрузка.
4.3. Нет таймаута/abort у запросов сохранения — app/static/js/api.js:1–32, app/static/js/editor.js:648–672
Зависший fetch навсегда оставляет saveInFlight = true, и автосейв больше не запускается. Ретраев и офлайн-очереди нет.
4.4. beforeunload не гарантирует сохранение — app/static/js/editor.js:380–390
При закрытии вкладки с несохранёнными правками браузер спрашивает подтверждение, но сохранение не форсируется; при потере сети правки пропадут.
4.5. Редактор фактически не адаптирован под планшеты — app/static/css/editor.css:39, app/templates/editor.html:8
Заглушка «откройте на компьютере» включается только ниже 760 px, а на 768–1023 px показывается полноценный редактор с двумя панелями и широким топбаром. Канвас остаётся крайне узким, кнопки топбара могут переполняться.
4.6. Нет клавиатурной навигации и focus-trap — app/static/js/canvas.js, app/static/js/palette.js, app/static/js/colorpicker.js
Элементы канваса недоступны с клавиатуры, в палитре/модалках нет удержания фокуса, colorpicker не имеет ролей/стрелок. Для инструмента проектирования это существенный минус доступности.
4.7. Мёртвый код онбординга — app/static/js/editor.js (maybeShowTour, state.firstRun)
Функция и флаг не используются; тур не показывается. Либо недоделанная фича, либо остаток.
4.8. Мак-детект по устаревшему navigator.platform — app/static/js/shortcuts.js:49
На новых iPad/гибридах определение неверное, из-за чего часть горячих клавиш (Ctrl/Cmd) работает не как ожидается.
4.9. Автовыбор первого шаблона в «Новом проекте» — app/static/js/new_project.js:60–70
Первый непустой шаблон выбирается и подставляет имя автоматически. Пользователь, желающий пустой проект, может случайно создать шаблонный.
4.10. Поиск в дашборде без пагинации — app/builder/views.py:30–42, app/static/js/dashboard.js:10–36
Все проекты и их полные data рендерятся в HTML, для каждого строится iframe с полным превью. При десятках проектов страница становится очень тяжёлой.
4.11. Поле thumbnail мертво — app/builder/models.py, app/builder/views.py:212–214
Нигде не генерируется. При дублировании проекта clone.thumbnail.name = project.thumbnail.name ссылается на тот же файл, а не копирует его. Функция превью не реализована.
4.12. Slug не обновляется при переименовании — app/builder/models.py:73–76
Project.save() генерирует slug только если он пуст. После смены названия публичный URL и имя файла экспорта остаются старыми — может путать пользователя (если это не намеренно).
4.13. Дублирование проекта оставляет устаревший exported_html — app/builder/views.py:200–216
Копируется и HTML, и данные. Публичная страница копии показывает контент оригинала под новым именем до первого сохранения из редактора.
4.14. 403 вместо 404 для чужих проектов — app/builder/views.py:20–24
PermissionDenied раскрывает существование чужого проекта. Обычно в таких API возвращают 404.
4.15. Нечисловой template_id даёт 500 — app/builder/views.py:68–70
get_object_or_404(Template, pk="abc") не ловит ValueError, только DoesNotExist. Крафченный POST роняет запрос.
4.16. Пустой public_raw отдаёт 200 с пустой страницей — app/builder/views.py:235–237
Вместо 404/409 при отсутствии экспорта возвращается успешный пустой документ — усложняет диагностику и кеширование.
4.17. Инвертированная логика no-cache middleware — app/config/middleware.py:20
Условие or not path.startswith("/api/") добавляет no-store ко всему, кроме API. Судя по комментарию, задумывалось наоборот — API-ответы как раз стоит защищать от кеша.
4.18. Тема и настройки не синхронизируются между вкладками — app/static/js/editor.js (localStorage theme)
Смена темы в одной вкладке не обновляет другую; мелочь, но заметная.


5. Инфраструктура, качество, сопровождение

5.1. Тестов нет — app/builder/tests.py:1
Файл содержит только комментарий. Ни API, ни рендерер, ни экспорт, ни права доступа не покрыты. Для проекта с таким объёмом клиентской логики это главный риск регрессий.
5.2. Зависимости не зафиксированы — requirements.txt
Везде >= без верхних границ/pin-ов и без lock-файла. Пересборка через месяц может внезапно сломаться на новой версии Django/Pillow/WhiteNoise.
5.3. Нет CI/lint/format-конфигов — корень проекта
Нет ни workflow, ни настроек ruff/eslint/prettier. Стиль и ошибки ловятся только вручную.
5.4. DJANGO_DEBUG по умолчанию 1 вне Docker — app/config/settings.py:14
При запуске runserver без переменных окружения включён debug с подробными страницами ошибок. Для локальной разработки нормально, но легко забыть на сервере.
5.5. Нет логирования и ADMINS — app/config/settings.py
Ошибки уходят только в stdout контейнера, нет структурированных логов и алертов. Диагностика прод-инцидентов затруднена.
5.6. public_preview не кешируется и не имеет ETag — app/builder/views.py:244–260
Каждый просмотр тянет iframe и полный HTML; для публичных страниц логично отдавать кеш-заголовки.
5.7. collectstatic и migrate на каждом старте контейнера — docker/entrypoint.sh:9–13
Для одного контейнера терпимо, но при горизонтальном масштабировании все реплики одновременно делают миграции и сборку статики. Нет отдельного шага сборки/релиза.
5.8. Healthcheck зависит от наличия curl — docker-compose.yml:22, Dockerfile:12–15
Работает, но добавляет лишний пакет в образ; можно обойтись Python-проверкой. Мелочь.
5.9. Файл db.sqlite3 может попасть в контекст сборки — .dockerignore:10
Исключён, но локальная БД лежит в app/; при ручной сборке без .dockerignore (или при копировании проекта) можно случайно утащить данные в образ. Риск низкий.
5.10. ASSET_VERSION зависит от наличия ключа hash в манифесте — app/config/context_processors.py, app/config/settings.py:129–136
При смене storage-бэкенда/формата манифеста версия молча станет 1, и кеш снова начнёт отдавать старое. Хрупкая связка.


6. Мелочи и пограничные случаи

- 6.1. finishDraw не ограничивает нарисованный фрейм границами канваса — можно утащить далеко за пределы (canvas.js:300–360).
- 6.2. addImageFromAsset центрирует картинку по X, но не по Y относительно точки дропа (state.js, images.js).
- 6.3. Вставка ассета из панели всегда в (80,80), элементы накладываются друг на друга.
- 6.4. syncValues не обновляет часть контролов (boxShadow, hidden) при внешнем изменении — панель может показывать устаревшее.
- 6.5. onPanelInput обрабатывает и input, и change — лишние коммиты при блюре (panels.js:108–109).
- 6.6. Palette строит действия один раз при открытии; после изменения структуры проекта список устаревает до переоткрытия (palette.js).
- 6.7. parseColor не понимает именованные цвета (white, transparent) — colorpicker открывается с неверным цветом (colorpicker.js).
- 6.8. У colorpicker нет клавиатурного управления и фокус-стилей (colorpicker.js).
- 6.9. toast строит innerHTML из iconsUrl; при отсутствии window.BUILDER получится битая ссылка (toast.js).
- 6.10. suppressClick/beforeunload флаги не сбрасываются при отмене навигации — редкий ложный prompt (editor.js).
- 6.11. modules importmap строится по всем .js в каталоге; добавление не-модульного файла (например, вендорного) сломает карту (context_processors.py).
- 6.12. renderDocument всегда вставляет APPEAR_SCRIPT, даже если анимаций нет — лишние байты в каждом экспорте (render.js).
- 6.13. renderEmbed/safeUrl — чёрный список схем, а не allowlist; для CSS-фонов и data-URI SVG стоит перейти на строгий allowlist (render.js).
- 6.14. PAGES_SCRIPT вызывает window.scrollTo(0,0) при каждом переключении, включая неудачный hash — ломает возврат к позиции (render.js:939–961).
- 6.15. public_raw не выставляет X-Content-Type-Options: nosniff (views.py:232–240).
- 6.16. Нет Content-Security-Policy ни на одном уровне — усугубляет п. 1.2 (settings.py).
- 6.17. Asset.name/size не пересчитываются при замене файла (замены как таковой нет, но поле потенциально рассинхронизируется).
- 6.18. Project.data не валидируется по схеме: принимается любой JSON до 8 МБ, включая глубоко вложенные структуры, которые потом роняют рендерер (views.py:118–138).
- 6.19. Нет ограничения на количество страниц/фреймов/элементов — один проект может положить браузер и сервер.
- 6.20. public_preview не проверяет, что exported_html соответствует текущим данным; после правок через админку публичная версия остаётся старой.


Итог
Самые опасные проблемы — потеря правок из-за гонки автосохранения (1.1), stored XSS через сохраняемый HTML (1.2) и захардкоженный админ с известным паролем в проде (1.3). Следом идут небезопасные прод-настройки (1.4–1.6) и конкурентные перезаписи (1.7). В редакторе больше всего досаждают гонки автосейва/переключения страниц (2.1–2.3) и неверные координаты при кросс-фреймовых операциях (2.4–2.6). В экспорте — неработающие якоря (3.1), сломанные превью на дашборде (3.2) и устаревшие стили без версионирования (3.3).
