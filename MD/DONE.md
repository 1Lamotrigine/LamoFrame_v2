# LamoFrame — что сделано и как это устроено

Документ описывает итоговое состояние проекта: стек, архитектуру, реализованные
возможности, исправленные проблемы и способы проверки. Это отчёт «что и для чего
использовалось», а не инструкция по установке (она — в `README.md`).

Дата фиксации состояния: **3 ноября 2026**.

---

## 1. Что представляет собой проект

**LamoFrame** — учебный конструктор сайтов со свободным холстом, похожий по идее
на Figma/Webflow, но проще:

- пользователь создаёт проект из шаблона или с пустого холста;
- собирает страницу из фреймов (секций) и элементов (текст, заголовок, кнопка,
  ссылка, изображение, фигура, линия, iframe);
- делает несколько страниц, общие шапку и подвал;
- настраивает адаптив в двух режимах: автоматический и ручной (отдельные макеты
  для планшета и телефона);
- сохраняет проект на сервере и экспортирует готовый сайт в ZIP;
- может открыть публичную read-only версию страницы.

Проект специально сделан **без фронтенд-сборщика**: браузер загружает ES-модули
напрямую. Это уменьшает инфраструктуру и делает учебный код прозрачным.

| django-allauth | 65.4.1 | OAuth 2.0-вход через Google (плюс служебные account/socialaccount URL) |
| Docker + Docker Compose | — | Воспроизводимый запуск, тома для БД и media, healthcheck |

### Фронтенд

| Технология | Для чего используется |
| --- | --- |
| Vanilla JavaScript, ES-модули | Вся логика редактора; без React/Vue и без сборщика |
| CSS-переменные (`tokens.css`) | Единая тема, размеры, цвета, светлая/тёмная тема |
| Import map | Версионирование ES-модулей через `?v=ASSET_VERSION` |
| Pointer Events | Единая обработка мыши/пера/тача: drag, resize, marquee, пан, зум |
| HTML5 Drag and Drop | Перетаскивание элементов из библиотеки на холст, ассетов, слоёв |
| `<iframe sandbox>` | Изоляция превью и публичной страницы |
| `localStorage` | Тема редактора и ширина левой панели |
| `fetch` + `AbortController` | API-запросы с таймаутом |
| `FileReader`, `Blob`, `URL.createObjectURL` | Встраивание картинок, скачивание ZIP |
| `ResizeObserver`, `IntersectionObserver` | Пересчёт масштаба сайта и анимации появления |
| Собственный ZIP-writer | Экспорт без внешних библиотек (`zip.js`) |
| Локальный шрифт Inter (woff2) | Единая типографика без обращений к Google Fonts |

### Принципиальные решения

1. **Один рендерер на всё.** `app/static/js/render.js` используется и для холста
   редактора, и для превью, и для экспорта. Поэтому редактор и готовый сайт
   меньше расходятся.
2. **Документ — это JSON.** Вся структура проекта хранится в `Project.data`, а не
   в десятках связанных таблиц. Это упрощает undo/redo, копирование, экспорт и
   миграции формата.
3. **Сервер не рендерит сайт.** Сервер хранит JSON и готовый HTML, а сборку
   страницы выполняет браузер. Это позволило сделать офлайн-экспорт и не
   тащить на бэкенд шаблонизатор сайта.
4. **Оптимистическая блокировка.** Клиент присылает версию документа, которую
   открыл; при конфликте сервер отвечает `409`, а не молча затирает чужие правки.

## 4. Модель данных

### Таблицы

| Модель | Поля | Назначение |
| --- | --- | --- |
| `Project` | `title`, `slug`, `owner`, `data` (JSON), `exported_html`, `thumbnail`, `created_at`, `updated_at` | Проект пользователя |
| `Asset` | `project`, `file`, `name`, `size`, `created_at` | Загруженное изображение проекта |
| `Template` | `title`, `slug`, `description`, `preview`, `data` (JSON), `sort_order` | Готовый шаблон сайта |

### Структура `Project.data` (версия 3)

```jsonc
{
  "version": 3,
  "meta": { "title": "...", "description": "...", "lang": "ru" },
  "settings": {
    "width": 1200,
    "bg": "#ffffff",
    "font": "system",
    "responsive": { "auto": true, "device": "desktop" }
  },
  "activePageId": "p_home",
  "pages": [
    {
      "id": "p_home",
      "name": "Главная",
      "slug": "index",
      "frames": [ /* фреймы десктопа */ ],
      "devices": {
        "tablet": { "frames": [] },
        "phone":  { "frames": [] }
      }
    }
  ],
  "components": {
    "header": { /* общий фрейм шапки */ },
    "footer": { /* общий фрейм подвала */ },
    "devices": {
      "tablet": { "header": {}, "footer": {} },
      "phone":  { "header": {}, "footer": {} }
    }
  },
  "groups": {
    "g_xxx": { "id": "g_xxx", "name": "Группа 1" }
  }
}
```

Фрейм содержит `id`, `name`, координаты `x/y/w/h`, фон, радиус, `locked`,
`hidden`, `role` (для шапки/подвала) и `elements`. Элемент содержит `type`,
`x/y/w/h`, `z`, `rotation`, `style`, `props`.

Во время работы редактор держит ещё и **runtime-поле `doc.frames`** — плоский
список фреймов текущей страницы и устройства, собранный из `pages` и
`components`. При сохранении `serializeDoc()` удаляет этот дубль, чтобы в БД не
попадали производные данные.

## 6. Как устроены ключевые части

### 6.1. Состояние и история (`state.js`)

- Единый объект `state`: документ, выделение, активный фрейм, зум/пан, тема,
  история, состояние сохранения.
- `commit(mutator)` — изменение + запись в историю + событие `doc`.
- `update(mutator)` — транзиентное изменение без истории (drag/resize).
- История ограничена 50 шагами.
- `serializeDoc()` синхронизирует runtime-фреймы, убирает дубль `frames` и
  возвращает снимок для сохранения.
- `migrateDoc()` поднимает старые документы (v1/v2) до v3: переносит `sections`
  во `frames`, нормализует страницы, компоненты, устройства и группы.

### 6.2. Холст (`canvas.js`)

- Рендер секций через `render.js` с `editor: true`.
- Pointer Events для:
  - выделения кликом и Shift-кликом;
  - рамки выделения;
  - перемещения элементов и фреймов;
  - ресайза 8 маркерами и поворота;
  - пана (Space + drag, средняя кнопка).
- Привязка к краям/центрам фрейма и соседним элементам (`snapping.js`).
- Двойной клик — инлайн-редактирование текста.
- Drop-обработчик принимает файлы и элементы библиотеки.
- После геометрических изменений фреймов вызывается `restackFrames()`, поэтому
  секции не накладываются.

### 6.3. Рендерер (`render.js`)

Один модуль отвечает за:

- HTML элемента каждого типа;
- типографику, фон, рамку, тень, прозрачность, поворот;
- ссылки: внешние, на страницу (`page:`), на якорь (`#anchor`);
- безопасные URL и экранирование;
- сборку дерева вложенных фреймов;
- автоадаптив: масштабирование канваса и CSS-рефлоу на планшете/телефоне;
- ручной адаптив: три макета и медиазапросы;
- появление элементов по скроллу (`IntersectionObserver`);
- скрипт переключения страниц в однофайловом экспорте;
- отдельные функции для многофайлового экспорта (`buildStylesheet`,
  `buildMainScript`, `renderBundlePage`).

### 6.4. Экспорт (`bundle.js` + `zip.js`)

Два режима:

1. **Однофайловый HTML** — используется для сохранения `exported_html` и
   публичной страницы. Картинки превращаются в `data:` URI, внешних
   зависимостей нет.
2. **ZIP с сайтом** — скачивается кнопкой «Экспорт»:
   ```
   index.html
   another-page.html
   assets/
     css/style.css
     js/main.js
     images/*
   ```
   ZIP собирается собственным writer'ом: CRC32, локальные заголовки, центральный
   каталог. Без JSZip и других зависимостей.

Особенности:

- изображения обрабатываются последовательно — ZIP детерминирован;
- data URI декодируются в байты, а не в Unicode-текст;
- внешние картинки без CORS остаются внешними ссылками;
- страницы получают имена из slug, коллизии разрешаются суффиксом `-2`.

### 6.5. Сохранение

- Автосохранение через 1 секунду после последнего не-транзиентного изменения.
- Ручное `⌘S`.
- Индикатор: «Сохранено», «Есть изменения», «Сохраняем…», «Ошибка».
- Защита от гонки: счётчик ревизий документа. Если во время запроса пользователь
  продолжил редактировать, состояние не объявляется сохранённым, а сохранение
  ставится в очередь.
- `saveInFlight` освобождается в `finally`, зависший запрос не блокирует
  автосохранение навсегда.
- Перед экспортом текущее сохранение дожидается завершения.
- Серверная оптимистическая блокировка: `base_updated_at` → `409` при конфликте.

### 6.6. Адаптив

**Авто:**

- до 1023.98 px — планшетный рефлоу;
- до 767.98 px — телефонный рефлоу;
- выше — масштабирование канваса под ширину окна с ограничением 1680 px;
- фон секции растягивается на всю ширину, контент центрируется.

**Ручной:**

- при выключении «Авто» для каждой страницы создаются макеты `tablet` (768 px) и
  `phone` (390 px);
- макеты собираются из десктопа эвристикой: элементы разбиваются на карточки и
  одиночные блоки, затем выстраиваются в поток с подходящими размерами;
- пользователь может править каждый макет отдельно;
- кнопка «Пересобрать макет из десктопа» сбрасывает выбранное устройство;
- при экспорте рендерятся все три макета, показ — через CSS-медиазапросы.

### 6.7. Шапка и подвал

- Хранятся отдельно от страниц, поэтому правка на одной странице видна на всех.
- На холсте позиционируются над верхним и под нижним фреймом.
- При экспорте порядок жёсткий: header → контент → footer.
- Для ручного адаптива есть отдельные версии шапки/подвала под каждое
  устройство; если их нет, используется десктопная версия (fallback).

### 6.8. Группы

- У элементов есть `groupId`.
- Метаданные групп лежат в `doc.groups`.
- Выбор любого элемента группы расширяется до всей группы (`expandGroups`).
- В слоях группа — сворачиваемый блок с переименованием и разгруппировкой.
- Битые группы (меньше двух элементов) автоматически распадаются при загрузке.

## 7. Бэкенд: маршруты и поведение

| Метод и URL | Назначение |
| --- | --- |
| `GET /` | Дашборд проектов пользователя, поиск |
| `GET /new/` | Выбор шаблона |
| `POST /projects/create/` | Создание проекта |
| `GET /editor/<pk>/` | Редактор |
| `GET /api/projects/<pk>/` | Загрузка проекта (JSON + список ассетов) |
| `PUT /api/projects/<pk>/` | Сохранение `data`, `html`, `title`; проверка версии |
| `POST /api/projects/<pk>/assets/` | Загрузка изображения |
| `GET /projects/<pk>/export/` | Скачивание сохранённого HTML |
| `POST /projects/<pk>/duplicate/` | Дублирование проекта |
| `POST /projects/<pk>/delete/` | Удаление проекта и его файлов |
| `GET /p/<slug>/` | Публичное превью в iframe |
| `GET /p/<slug>/raw/` | Сам экспортированный документ |
| `/accounts/login/`, `/accounts/signup/` | Вход и регистрация |
| `/accounts/google/login/` | OAuth-флоу Google |
| `/admin/` | Админка Django |

Серверные проверки:

- проект доступен только владельцу; чужой проект отдаёт `404`, а не `403`, чтобы
  не раскрывать его существование;
- документ проверяется на версию, наличие фреймов, лимиты страниц (50), фреймов
  (400), элементов (5000), глубину вложенности (40) и размер (8 МБ);
- экспорт ограничен 12 МБ;
- загрузка: JPEG/PNG/WebP/GIF, до 2 МБ, до 200 файлов на проект, проверка через
  Pillow, включая `DecompressionBombError`;
- публичный `raw` отдаёт `ETag`, `304`, `X-Content-Type-Options: nosniff` и CSP
  `sandbox`, чтобы пользовательский HTML не мог читать cookie приложения;
- удаление проекта удаляет и файлы ассетов/миниатюру.

## 8. Исправления по аудиту (`MD/ANALIS.md`)

### Критичное

| Проблема | Решение |
| --- | --- |
| 1.1 Гонка автосохранения теряла правки | Счётчик ревизий, сравнение ревизии после ответа, очередь сохранения, освобождение `saveInFlight` в `finally` |
| 1.2 Stored XSS в публичном HTML | CSP `sandbox` + `nosniff` на `public_raw`; sandbox-iframe в превью |
| 1.3 Захардкоженные demo/admin-пароли | `SEED_DEMO=0` по умолчанию, пароли из окружения или случайные, админ только с `ADMIN_PASSWORD`, подсказка убрана со страницы входа |
| 1.4 Небезопасные прод-настройки | Генерация случайного `SECRET_KEY`, `ALLOWED_HOSTS` без `*`, `SECURE_*`, HSTS, `CSRF_TRUSTED_ORIGINS`, логирование |
| 1.5 `WHITENOISE_USE_FINDERS` в проде | Включается только в `DEBUG` |
| 1.6 SQLite + 3 воркера | Gunicorn: 1 воркер, 4 потока, таймаут блокировки БД 20 с |
| 1.7 Конкурентные перезаписи | `base_updated_at` + ответ `409` |
| 1.8 Бомбы и лимиты загрузок | Лимит файлов, отлов `DecompressionBombError` |
| 1.9 Удаление проекта не чистило файлы | Удаление ассетов и миниатюры перед удалением записи |
| 1.10 Media через Django | Оставлено осознанно как ограничение учебного проекта; добавлены валидация и лимиты |

### Логика редактора

- транзиентные drag/resize больше не запускают автосохранение;
- переключение страниц не помечает проект изменённым;
- общие шапка/подвал больше не «переезжают» при смене страницы;
- кросс-фреймовые drag/resize, координаты в панели, выравнивание и распределение
  переведены на абсолютные координаты;
- colorpicker и поля свойств не спамят историю: предпросмотр отделён от коммита;
- новые фреймы в ручном режиме получают ширину текущего устройства;
- `Esc` при переименовании отменяет изменение, а не коммитит старое значение;
- маркиз пропускает скрытые и заблокированные элементы;
- рисование фигуры — один шаг undo;
- перенос элемента в общий header/footer запрещён.

### Экспорт и адаптив

- `#anchor` больше не перехватывается скриптом страниц;
- превью дашборда и «Нового проекта» считает высоту только видимой страницы и
  реальную ширину макета;
- добавлен cache-busting для CSS и иконок;
- компоненты планшета/телефона имеют fallback на десктоп;
- уровень заголовка округляется;
- ZIP детерминирован, data URI декодируются в байты;
- ложное «сервер недоступен» при экспорте убрано.

### Инфраструктура и качество

- у API-запросов появился таймаут;
- редактор адаптирован под планшетную ширину;
- исправлены копирование миниатюры, устаревший HTML копии, нечисловой
  `template_id`, пустой `public_raw` (`404`) и no-cache middleware;
- тема синхронизируется между вкладками;
- добавлены Django-тесты;
- зависимости закреплены точными версиями.

## 9. Безопасность и надёжность

Что уже есть:

- CSRF на всех изменяющих запросах;
- разграничение доступа по владельцу проекта;
- проверка версии документа при сохранении;
- валидация и лимиты JSON, HTML и загрузок;
- CSP `sandbox` и `nosniff` для пользовательского HTML;
- экранирование текста и атрибутов в рендерере;
- allowlist для ссылок (`http`, `https`, `mailto`, якоря);
- безопасный `next` при входе/регистрации (защита от open redirect);
- `SECURE_*`, HSTS и secure-cookies включаются на HTTPS-деплое;
- контейнер работает не от root;
- healthcheck проверяет и страницу, и CSS.

Осознанные ограничения:

- SQLite остаётся однописательной базой; для многопользовательской нагрузки нужен
  PostgreSQL;
- media в проде отдаёт Django, а не nginx;
- CSP `sandbox` защищает от чтения cookie, но не является полноценным
  санитайзером произвольного HTML — для публичного сервиса нужен отдельный
  санитайзер;
- ресайз повёрнутых элементов считается по неповёрнутому bounding box;
- эвристика карточек в авто-рефлоу не идеальна для нестандартных макетов;
- внешние изображения без CORS не попадают в ZIP;
- нет CI и линтеров, тесты только серверные (JS проверяется синтаксически).

## 11. Запуск

### Docker

```bash
cp .env.example .env      # при необходимости заполнить ключи
docker compose up --build -d
docker compose ps         # дождаться healthy
```

Открыть: http://127.0.0.1:8000/

### Локально

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cd app
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

### Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `DJANGO_DEBUG` | `0` — прод, `1` — отладка |
| `DJANGO_SECRET_KEY` | секретный ключ |
| `DJANGO_ALLOWED_HOSTS` | разрешённые хосты |
| `DJANGO_SECURE_COOKIES`, `DJANGO_HTTPS` | secure-cookies и HTTPS-режим |
| `SEED_DEMO` | создать демо-данные |
| `DEMO_PASSWORD`, `ADMIN_PASSWORD` | пароли демо-пользователя и админа |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | OAuth-клиент Google |
| `SQLITE_PATH` | путь к базе в контейнере |

## 12. Итог

Сделано полноценное учебное веб-приложение:

- Django-бэкенд с авторизацией, регистрацией, Google OAuth, API и админкой;
- собственный редактор на чистом JavaScript с историей, слоями, группами,
  страницами, компонентами, адаптивом и экспортом;
- два формата экспорта: автономный HTML и многофайловый ZIP;
- исправлены критичные проблемы из аудита: потеря правок, XSS, пароли по
  умолчанию, конкурентные перезаписи;
- добавлены тесты и закреплены зависимости;
- проект запускается локально и в Docker.

Главный принцип реализации: **один JSON-документ → один рендерер → холст,
превью и экспорт выглядят одинаково**.
