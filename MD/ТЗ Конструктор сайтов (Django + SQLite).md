# ТЗ: Конструктор сайтов (прототип)

Веб-конструктор сайтов для демо: пользователь собирает страницу на свободном холсте, как в Figma, и скачивает её одним файлом `index.html`. Стек: vanilla Django + SQLite + vanilla JS, ориентировочный срок 12–16 рабочих дней.

## Цель и критерий успеха

Демо успешно, если за 5 минут человек без инструкций собирает страницу из шаблона, правит её и скачивает `index.html`, который открывается по `file://` и выглядит так же, как в редакторе (расхождение до 1 px).

- **В рамках:** холст со свободным перемещением, слои и свойства, шаблоны, загрузка картинок, превью, экспорт одним файлом.
- **Вне рамок:** многопользовательская работа, хостинг и домены, CMS, бэкенд форм, пользовательский код, оплата, SEO кроме title и description.

## Как это устроено

&#91;embedded content: поток данных · 6 блоков\]

Редактор хранит документ как JSON, `render.js` превращает его в HTML и CSS для холста, превью и экспорта. Django только сохраняет JSON и готовую HTML-строку, поэтому «Скачать» работает и с дашборда.

1. **Документ = JSON** в `Project.data`, у схемы есть `version`.
2. **Один рендерер.** Холст, превью и экспорт строятся одним `render.js`, поэтому расхождения «в редакторе так, в файле иначе» исключены.
3. **Абсолютное позиционирование внутри секций.** Артборд 1200 px по центру, у элемента `x, y, w, h`; секции задают вертикальную структуру и фон.
4. **Безопасность.** Превью только в sandbox iframe, загрузки проверяются на сервере.

## Этапы

Этапы 0–7 обязательны, этап 8 делается по остатку времени. Сроки ориентировочные, для одного разработчика с AI-инструментами.

| Этап | Срок | Результат | Готово, когда |
| --- | --- | --- | --- |
| 0. Каркас | 0,5–1 дн | Проект Django, приложение `builder`, модели Project, Asset, Template, логин, админка | Сервер стартует, проект создаётся через админку |
| 1. Дашборд | 1 дн | Список проектов, создание из шаблона, дублирование, удаление, API GET/PUT документа | Проект открывается на `/editor/<id>/`, JSON сохраняется и читается |
| 2. Холст | 2–3 дн | Артборд, зум и пан, добавление элементов, выделение, перенос, ресайз, секции | Страница из 5–6 элементов собирается мышью, 60 fps на \~100 элементах |
| 3. Свойства и слои | 2 дн | Панель свойств, правка текста на холсте, панель слоёв, автосохранение | Любой параметр элемента меняется без перезагрузки и сохраняется |
| 4. «Как в Figma» | 2–3 дн | Мультивыделение, snapping и направляющие, поворот, Undo/Redo, копирование, горячие клавиши | Страница за 10 минут собирается без желания открыть Figma, undo не ломает состояние |
| 5. Экспорт и превью | 1–2 дн | Рендерер, экспорт `index.html`, превью в sandbox iframe | Экспорт открывается по `file://` и совпадает с превью |
| 6. Файлы и шаблоны | 1 дн | Загрузка картинок, 3 шаблона (лендинг, портфолио, визитка), миниатюры проектов | Сайт собирается со своими картинками, экспорт работает офлайн |
| 7. Полировка | 1–2 дн | Тема, анимации, тур, пустые состояния, тосты, окно горячих клавиш, вау-фичи | Демо-сценарий проходится без остановок в 4 браузерах |
| 8. Расширения (опц.) | 2–3 дн | Мобильный брейкпоинт, несколько страниц, анимации при скролле | Экспорт корректно выглядит на 375 px |

## Фичи для вау-эффекта

Четыре фичи низкой сложности (1, 3, 5, 8) стоит сделать наравне с Must: они дают больше всего эффекта на демо за минимум времени. Остальные идут по остатку, в этапе 7 или 8.

| № | Фича | Что делает | Сложность |
| --- | --- | --- | --- |
| 1 | Командная палитра (Ctrl+K) | Поиск по действиям и элементам: «добавить кнопку», «экспорт», «тёмная тема» | Низкая |

| 3 | Alt + перетаскивание и вставка из буфера | Alt даёт копию, Ctrl+V с картинкой в буфере создаёт изображение на холсте | Низкая |
| 4 | Тема сайта | Палитра и пара шрифтов в один клик перекрашивают весь сайт | Средняя |
| 5 | Выравнивание и распределение | Шесть кнопок выравнивания и распределение по горизонтали и вертикали | Низкая |
| 6 | Линейки и свои направляющие | Направляющие тянутся с линейки и притягивают объекты | Средняя |
| 7 | История версий | Снимки документа каждые несколько минут, откат одним кликом | Средняя |

| 9 | Переключатель устройств в превью | Desktop, планшет, телефон: показывает, как сайт ведёт себя на разной ширине | Низкая |

## Интерфейс

&#91;embedded content: раскладка редактора · 4 зоны\]

Слева библиотека, слои и файлы, в центре холст, справа свойства выбранного объекта. «Экспорт» выделен акцентом, потому что это главное действие экрана.

### Дизайн-токены

| Токен | Значение |
| --- | --- |
| Акцент | `#4F46E5` |
| Светлая тема: фон, поверхность, граница | `#F7F7F8`, `#FFFFFF`, `#E4E4E7` |
| Светлая тема: текст, приглушённый текст | `#18181B`, `#71717A` |
| Тёмная тема: фон, поверхность, граница | `#0F0F11`, `#18181B`, `#27272A` |
| Радиус и отступы | 8 px, шаг 4 / 8 / 16 px |
| Шрифт | Inter, подключён локально, не через CDN |
| Анимации | 120–180 мс: появление панелей, подсветка при наведении, тосты |
| Иконки | Один набор, inline SVG |

Токены лежат CSS-переменными в одном файле `tokens.css`.

### Правила UX

- **Первый запуск:** выбор шаблона, затем тур из 4 шагов (холст, элементы, свойства, экспорт), который можно пропустить.
- **Пустые состояния:** понятный текст и кнопка действия для пустого дашборда, пустой панели файлов и случая «ничего не выбрано».
- **Обратная связь:** курсоры по контексту (перенос, ресайз, поворот, текст), подсветка при наведении, размеры в подсказке при ресайзе, тосты на действия.
- **Горячие клавиши:** окно со списком по `?`.
- **Ошибка сохранения:** индикатор «Ошибка, повторить», данные в редакторе не теряются.

## Данные и API

Django только хранит и отдаёт JSON, вся логика редактора живёт в JS. Модули JS подключаются как ES-модули без сборщика: `state`, `canvas`, `selection`, `snapping`, `panels`, `layers`, `render`, `api`, `shortcuts`.

- **Project:** `title`, `slug`, `owner` (FK), `data` (JSONField), `exported_html` (TextField), `thumbnail`, `created_at`, `updated_at`.
- **Asset:** `project` (FK), `file` (ImageField), `name`, `size`.
- **Template:** `title`, `preview`, `data` (JSONField), загружается через fixtures.

Формат документа: версия схемы, секции, в секциях абсолютно позиционированные элементы. Типы элементов: text, heading, button, image, shape, line, embed.

```json
{
  "version": 1,
  "meta": {"title": "Мой сайт", "description": "", "lang": "ru"},
  "settings": {"width": 1200, "bg": "#ffffff", "font": "system"},
  "sections": [{
    "id": "s1", "name": "Hero", "height": 700, "bg": "#0f172a",
    "elements": [{
      "id": "e1", "type": "heading", "name": "Заголовок",
      "x": 120, "y": 180, "w": 600, "h": 120, "z": 1, "rotation": 0,
      "locked": false, "hidden": false,
      "props": {"text": "Привет", "href": ""},
      "style": {"fontSize": 56, "fontWeight": 700, "color": "#ffffff"}
    }]
  }]
}
```

| Метод | URL | Назначение |
| --- | --- | --- |
| GET | `/` | Дашборд со списком проектов |
| GET | `/new/` | Выбор шаблона |
| POST | `/projects/create/` | Создать проект из шаблона |
| GET | `/editor/<id>/` | Страница редактора |
| GET, PUT | `/api/projects/<id>/` | Прочитать или сохранить `data` и `html` |
| POST | `/api/projects/<id>/assets/` | Загрузить изображение |
| GET | `/projects/<id>/export/` | Скачать `index.html` |
| POST | `/projects/<id>/duplicate/` | Дублировать проект |
| POST | `/projects/<id>/delete/` | Удалить проект |
| GET | `/p/<slug>/` | Публичное превью, только чтение |

Ответы через `JsonResponse`, CSRF-токен в заголовке, DRF не используется.

## Экспорт

Экспортированный файл должен открываться двойным кликом, без сервера и интернета.

- **Один файл:** `<style>` в head, `<script>` в конце body и только если нужен (якорные ссылки, анимации, встраивания).
- **Изображения:** data URI (base64). Если файл больше 5 МБ, редактор предупреждает.
- **Шрифты:** системные стеки. Google Fonts через `<link>` как опция с пометкой «нужен интернет».
- **Семантика:** `<section>` по секциям, `<h1>`–`<h3>` для заголовков, `<a>` для ссылок и кнопок, `alt` у изображений, `<title>`, `meta description`, `lang`.
- **Узкие экраны:** в MVP артборд масштабируется под ширину окна через `transform: scale` с пересчётом высоты. Этап 8 заменяет это настоящим мобильным брейкпоинтом.
- **Проверка:** файл, открытый по `file://`, совпадает с превью до 1 px.

## Нефункциональные требования

| Параметр | Требование |
| --- | --- |
| Производительность | 60 fps при перетаскивании на \~100 элементах; DOM обновляется точечно, по id |
| Сохранение | Автосохранение с debounce 1 с, предупреждение при закрытии вкладки с несохранёнными правками |
| Undo/Redo | Снимки JSON-документа, глубина 50 шагов |
| Браузеры | Свежие Chrome, Edge, Firefox, Safari на десктопе; на мобильных показывается заглушка «Откройте на компьютере» |
| Безопасность | Превью только в `<iframe sandbox>`; загрузки: тип и размер до 2 МБ проверяются на сервере; `exported_html` не рендерится в самом приложении вне sandbox |
| Доступность | Видимый фокус, `aria-label` на иконках-кнопках, управление панелями с клавиатуры |
| Размер экспорта | Предупреждение при превышении 5 МБ |

## Риски и план урезания

Главный риск проекта в этапе 4: без snapping и undo редактор выглядит как игрушка, а UX заявлен приоритетом.

| Риск | Мера |
| --- | --- |
| Редактор на vanilla JS превращается в кашу | Строгое разделение модулей, один `state` с событиями, никакой логики в DOM-обработчиках |
| Undo/Redo ломается на разных типах действий | Хранить снимки документа, а не диффы; лимит 50 |
| Тормоза на сотнях элементов | Менять DOM точечно по id, `will-change: transform` только на перетаскиваемых |
| Текст расходится по шрифтам и ОС | Системные стеки, фиксированные размеры блоков, `overflow` задан явно |
| Экспорт ломает вёрстку на телефонах | В MVP масштабирование, брейкпоинт в этапе 8; честно говорить об этом на демо |
| Затягивание полировки | Жёсткий бюджет на этап 7, баги по чек-листу, без новых фич |

Если времени не хватает, режем в таком порядке, snapping и undo не трогаем:

1. Мобильный брейкпоинт и многостраничность (этап 8).
2. Вау-фичи средней сложности (№ 2, 4, 6, 7, 10, 11).
3. Тёмная тема редактора.
4. Группировка и поворот.
5. Тур и окно горячих клавиш.

## Демо-сценарий и приёмка

Проект готов, когда этот сценарий проходится без остановок в четырёх браузерах, экспорт открывается по `file://`, а snapping и undo работают.

1. Войти, нажать «Новый проект», выбрать шаблон «Лендинг».
2. Изменить заголовок двойным кликом, поменять цвет и шрифт в панели свойств.
3. Перетащить кнопку и выровнять её с заголовком по направляющим.
4. Загрузить свою картинку, поставить в секцию, скруглить углы.
5. Добавить секцию, дублировать в неё карточку (Ctrl+D), проверить undo и redo.
6. Открыть превью, нажать «Экспорт», открыть скачанный `index.html` из файловой системы.
7. Убедиться, что результат совпадает с редактором, а файл самодостаточен.
