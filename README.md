# Конструктор сайтов

Учебный прототип конструктора сайтов со свободным холстом: Django + SQLite на
бэкенде и ванильный JavaScript (ES-модули, без сборщика) на фронтенде.
Собранный проект экспортируется в один автономный файл `index.html`, который
открывается двойным кликом по `file://` без сервера.

## Возможности

**Обязательная часть**

- Дашборд проектов: создание, дублирование, удаление, поиск, живые миниатюры.
- Выбор из трёх готовых шаблонов или пустого холста.
- Холст шириной 1200 px со свободным позиционированием.
- Зум 10–400 % (кнопки, ⌘ + колесо, «вписать»), панорамирование (Space + drag,
  средняя кнопка, колесо).
- Элементы: текст, заголовок, кнопка, изображение, фигура, линия, iframe.
- Направляющие и привязка к краям/центрам секции и соседним элементам.
- Выделение (клик, Shift-клик, рамка), перемещение, ресайз 8 маркерами,
  поворот, стрелки для точного сдвига.
- Инлайн-редактирование текста двойным кликом.
- Панель свойств: позиция, размер, поворот, типографика, цвет, обводка, тень,
  прозрачность, ссылка, уровень заголовка.
- Слои: порядок, скрытие, блокировка, переименование, перенос между секциями.
- Автосохранение с индикатором состояния и ручным сохранением (⌘S).
- Undo/redo глубиной 50 шагов (⌘Z / ⇧⌘Z).
- Мультивыделение, выравнивание и распределение.
- Экспорт в один офлайн `index.html` (изображения встраиваются как data URI).
- **Адаптивный экспорт**: сайт занимает всю ширину экрана (фон не обрезается),
  на телефонах секции перестраиваются в вертикальный поток с крупным текстом,
  на больших экранах контент плавно масштабируется. Работает и в превью, и на
  публичной странице.
- Превью в песочнице (`sandbox` iframe) и публичный read-only просмотр.
- Загрузка изображений до 2 МБ с серверной проверкой формата и размера.

**Дополнительно**

- Копирование/вставка/дублирование, Alt-drag копия, вставка картинки из буфера.
- Командная палитра ⌘K с поиском по ключевым словам.
- Режим презентации (F), переключатель устройств в превью.
- Светлая/тёмная тема редактора, тосты, пустые состояния, онбординг-тур.
- Модальное окно горячих клавиш (?).

## Стек

- Python 3.13, Django 5.2, SQLite.
- Pillow для валидации изображений.
- django-allauth — вход/регистрация через Google (OAuth 2.0).
- Gunicorn + WhiteNoise для продакшен-раздачи (статику обслуживает WhiteNoise,
  загруженные картинки — Django).
- Фронтенд: ES-модули без бандлера, локальный шрифт Inter, единый рендерер
  `app/static/js/render.js` для холста, превью и экспорта.

## Запуск

### Вариант 1: Docker (рекомендуется)

```bash
docker compose up --build -d
```

Подождите, пока контейнер станет **healthy** (несколько секунд):

```bash
docker compose ps        # дождитесь статуса "healthy"
```

Затем откройте http://127.0.0.1:8000/ . При первом запуске контейнер сам
применяет миграции, собирает статику и создаёт демо-данные (пользователя `demo`
и пример проекта). База и загруженные картинки сохраняются в именованных
томах `sqlite-data` и `media-data`.

> **Важно:** `docker compose up -d` возвращает управление сразу, но приложению
> нужно ~3–6 секунд на инициализацию. Если открыть страницу раньше, стили могут
> не подгрузиться — просто обновите страницу после статуса `healthy`.
> Healthcheck проверяет и страницу, и CSS, так что «healthy» = «всё готово».

Переменные окружения контейнера (полный список — в `.env.example`):

| Переменная              | По умолчанию                     | Назначение                                    |
| ----------------------- | -------------------------------- | --------------------------------------------- |
| `DJANGO_DEBUG`          | `0`                              | `1` — отладка шаблонов; `0` — прод (по умолч.) |
| `DJANGO_SECRET_KEY`     | небезопасный dev-ключ            | задайте свой в проде                          |
| `DJANGO_ALLOWED_HOSTS`  | `localhost,127.0.0.1,[::1]`      | список хостов через запятую                   |
| `SEED_DEMO`             | `0`                              | `1` — создать демо-пользователя и проект      |
| `GOOGLE_CLIENT_ID`      | пусто                            | Client ID OAuth-клиента Google                |
| `GOOGLE_CLIENT_SECRET`  | пусто                            | Client Secret OAuth-клиента Google            |
| `SQLITE_PATH`           | `/data/db.sqlite3`               | путь к файлу базы (в томе)                    |

Полный список переменных удобно вести в `.env` (см. `.env.example`): файл
подхватывается `docker compose` автоматически и в репозиторий не попадает.

В режиме по умолчанию (`DEBUG=0`) статика отдаётся с **хеш-именами**
(`base.8a4bc8c52faa.css`) и заголовком `Cache-Control: immutable`, а HTML — с
`no-store`. Поэтому после пересборки образа браузер гарантированно получает
актуальный CSS и «слетевших» стилей не бывает.

### Вариант 2: локально (venv)

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cd app
python manage.py migrate          # создаст таблицы и загрузит 3 шаблона
python manage.py seed_demo        # демо-пользователь и пример проекта
python manage.py runserver
```

Откройте http://127.0.0.1:8000/

Тестовые учётные записи создаются командой `seed_demo`. Пароли задаются
переменными `DEMO_PASSWORD` и `ADMIN_PASSWORD`; если их не задать, команда
сгенерирует случайные и напечатает в логе.

| Логин | Пароль            | Роль                        |
| ----- | ----------------- | --------------------------- |
| demo  | `$DEMO_PASSWORD`  | обычный доступ              |
| admin | `$ADMIN_PASSWORD` | суперпользователь (`/admin/`) |

## Вход и регистрация

- **`/accounts/login/`** — вход по логину и паролю.
- **`/accounts/signup/`** — регистрация (логин, необязательный email, пароль).
  После создания аккаунта пользователь сразу авторизуется.
- **Вход через Google** — кнопка «Войти через Google» на обеих страницах.

### Настройка входа через Google

Провайдер подключается только если заданы ключи — без них кнопка не
показывается, а остальной вход работает как обычно.

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте
   **OAuth client ID** типа *Web application*.
2. В *Authorized redirect URIs* добавьте:
   `http://localhost:8000/accounts/google/login/callback/`
   (для прода — ваш домен: `https://ваш-домен/accounts/google/login/callback/`).
3. Пропишите ключи в `.env` (скопируйте из `.env.example`):

   ```bash
   GOOGLE_CLIENT_ID=…
   GOOGLE_CLIENT_SECRET=…
   ```

4. Перезапустите приложение: `docker compose up -d` (или `runserver` локально).

При первом входе через Google аккаунт создаётся автоматически, логин
генерируется из email (при коллизии добавляется суффикс).

## Экспорт

Кнопка «Экспорт» собирает автономный документ в браузере, сохраняет его в поле
`Project.exported_html` и отдаёт файлом `index.html`. Все изображения
превращаются в data URI, внешних зависимостей нет. Публичная страница
`/p/<slug>/` показывает тот же документ в песочнице.

### Адаптивность

Сайт заполняет **всю ширину окна на любом экране** — фон секций не обрезается
белыми полосами. Как это устроено:

- Каждая секция занимает всю ширину окна и красит фон во всю ширину.
- Внутри секции лежит «канвас» шириной макета, который масштабируется
  коэффициентом `--sb-k = ширина_окна / ширина_макета` (вычисляется в браузере
  на `resize`). На широких мониторах контент растёт до 1680 px и центрируется,
  дальше растягивается только фон — так текст не превращается в гигантский.
- **≤ 767 px (телефоны)** — масштаб выключается, и канвас становится
  вертикальным потоком: абсолютные координаты игнорируются, элементы
  выстраиваются друг под другом в порядке слоёв (`z-index`), заголовки и текст
  масштабируются через `clamp()`, картинки и встраивания растягиваются по
  ширине (16:10 и 16:9), кнопки — по размеру текста, фигуры сохраняют
  пропорции. Это настоящий рефлоу, а не сжатие макета.

Горизонтальной прокрутки нет ни на 320 px, ни на 2560 px.

Переключатель устройств в превью (компьютер / планшет / телефон) показывает
все режимы без экспорта файла.

## Заметки по разработке

- Шаблоны подгружаются автоматически сигналом `post_migrate` из фикстуры;
  повторный `loaddata` не требуется.
- `SECRET_KEY`, `DEBUG` и хосты настраиваются переменными окружения
  `DJANGO_SECRET_KEY`, `DJANGO_DEBUG`. Значения по умолчанию — только для
  локальной разработки.
- В `DEBUG` медиафайлы отдаёт сам Django через `static()` в `config/urls.py`.
  Для продакшена настройте отдельный веб-сервер для `/media/` и `/static/`.
