# LamoFrame — конструктор сайтов

Учебный прототип конструктора сайтов со свободным холстом: Django + SQLite на
бэкенде и ванильный JavaScript (ES-модули, без сборщика) на фронтенде.

Редактор позволяет собрать многостраничный адаптивный сайт, сохранить его на
сервере и скачать готовый проект в ZIP. Отдельно сохраняется автономный HTML для
публичного превью — он открывается без сервера и внешних зависимостей.

## Возможности

### Проекты и холст

- Дашборд проектов: создание, дублирование, удаление, поиск, живые миниатюры.
- Три готовых шаблона (лендинг, портфолио, визитка) или пустой холст.
- Холст шириной 1200 px со свободным позиционированием.
- Фреймы-секции: создание, рисование, перемещение, ресайз, дублирование.
- Фреймы автоматически выстраиваются друг под другом с зазором 24 px; изменение
  высоты секции сдвигает все нижние, поэтому они не наслаиваются.
- Вложенные фреймы: фрейм внутри другого рендерится внутри него, а не отдельной
  секцией.
- Зум 10–400 % (кнопки, ⌘ + колесо, «вписать»), панорамирование (Space + drag,
  средняя кнопка, колесо).
- Направляющие и привязка к краям/центрам секции и соседним элементам.

### Элементы и свойства

- Текст, заголовок, кнопка, ссылка, изображение, фигура, линия, iframe.
- Инлайн-редактирование текста двойным кликом.
- Панель свойств: позиция, размер, поворот, типографика, цвет, обводка, тень,
  прозрачность, ссылка, уровень заголовка.
- Два уровня выравнивания текста:
  - внутри текстового блока — по левому краю, центру, правому краю и по ширине;
  - внутри рамки элемента — к верху, середине или низу.
- Ссылки: внешние, на якорь (`#anchor`) и на другую страницу проекта.
- Загрузка изображений до 2 МБ с серверной проверкой формата и размера.
- Перетаскивание элементов из библиотеки прямо на холст.
- Перетаскивание картинок из файловой системы на холст и вставка из буфера.

### Слои, группы и выделение

- Слои: порядок, скрытие, блокировка, переименование, перенос между секциями.
- Группы элементов: создание, разворачивание/сворачивание, переименование,
  разгруппировка. Группа ведёт себя как единое выделение.
- Мультивыделение: Shift-клик, рамка выделения на холсте, `⌘A`.
- Групповое перемещение, удаление и дублирование элементов и фреймов.

### Страницы, шапка и подвал

- Несколько страниц с собственным холстом.
- Создание, дублирование, удаление и переименование страниц.
- Шапка и подвал — общие компоненты: правка на одной странице меняет их на всех.
- При экспорте шапка всегда идёт сверху, подвал — снизу, независимо от их
  координат на холсте.
- Ссылки на страницы добавляются в шапку через панель свойств.
- Библиотека готовых блоков: шапка, подвал, первый экран, преимущества,
  о компании, призыв к действию, галерея, контакты.

### Адаптив

- Режим **«Авто»**: экспорт сам масштабирует макет и перестраивает секции в
  вертикальный поток на планшете и телефоне.
- Ручной режим: отдельные макеты для десктопа, планшета (768 px) и смартфона
  (390 px) на каждой странице.
- При выключении «Авто» планшетный и телефонный макеты собираются из десктопа
  как осмысленный поток блоков, а не как уменьшенная копия.
- Кнопка «Пересобрать макет из десктопа» сбрасывает выбранное устройство.
- Переключатель устройств в превью: компьютер / планшет / телефон.

### Сохранение и экспорт

- Автосохранение с индикатором состояния и ручным сохранением (`⌘S`).
- Защита от гонки автосохранения и от конкурентных правок из разных вкладок.
- Undo/redo глубиной 50 шагов (`⌘Z` / `⇧⌘Z`).
- Экспорт сайта в ZIP:
  ```
  index.html
  another-page.html
  assets/
    css/style.css
    js/main.js
    images/*
  ```
- Все страницы получают имена из slug; изображения складываются в `assets/images`.
- Превью в песочнице (`sandbox` iframe) и публичный read-only просмотр.
- Для публичной версии сохраняется автономный HTML: картинки встроены как data
  URI, внешних зависимостей нет.

### Редактор и UX

- Перетаскиваемая граница левой панели (200–560 px), ширина запоминается.
- Командная палитра `⌘K` с поиском по ключевым словам.
- Режим презентации (`⇧F`), горячие клавиши (`?`).
- Светлая/тёмная тема, синхронизация темы между вкладками.
- Тосты, пустые состояния, онбординг-тур.
- Адаптация интерфейса под планшетную ширину.

## Стек

- Python 3.13, Django 5.2, SQLite.
- Pillow — проверка загружаемых изображений.
- django-allauth — вход и регистрация через Google (OAuth 2.0).
- Gunicorn + WhiteNoise — продакшен-запуск и раздача статики.
- Фронтенд: ES-модули без бандлера, локальный шрифт Inter, единый рендерер
  `app/static/js/render.js` для холста, превью и экспорта.
- Собственный ZIP-writer на JavaScript — без внешних библиотек.

## Запуск

### Вариант 1: Docker (рекомендуется)

```bash
cp .env.example .env      # при необходимости заполните ключи
docker compose up --build -d
docker compose ps         # дождитесь статуса healthy
```

Откройте http://127.0.0.1:8000/ .

При первом запуске контейнер сам применяет миграции, собирает статику и при
`SEED_DEMO=1` создаёт демо-данные. База и загруженные картинки сохраняются в
именованных томах `sqlite-data` и `media-data`.

> **Важно:** `docker compose up -d` возвращает управление сразу, но приложению
> нужно несколько секунд на инициализацию. Healthcheck проверяет и страницу, и
> CSS, поэтому статус `healthy` означает, что всё готово.

Переменные окружения (полный список — в `.env.example`):

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `DJANGO_DEBUG` | `0` | `1` — отладка шаблонов; `0` — прод |
| `DJANGO_SECRET_KEY` | генерируется в проде | секретный ключ |
| `DJANGO_ALLOWED_HOSTS` | `localhost,127.0.0.1,[::1]` | разрешённые хосты |
| `DJANGO_SECURE_COOKIES` | `0` | secure-cookies на HTTPS |
| `DJANGO_HTTPS` | `0` | редирект на HTTPS и доверие `X-Forwarded-Proto` |
| `SEED_DEMO` | `0` | `1` — создать демо-пользователя и проект |
| `DEMO_PASSWORD` | случайный | пароль пользователя `demo` |
| `ADMIN_PASSWORD` | пусто | пароль администратора; без него админ не создаётся |
| `GOOGLE_CLIENT_ID` | пусто | Client ID OAuth-клиента Google |
| `GOOGLE_CLIENT_SECRET` | пусто | Client Secret OAuth-клиента Google |
| `SQLITE_PATH` | `/data/db.sqlite3` | путь к файлу базы в контейнере |

В режиме `DEBUG=0` статика отдаётся с хеш-именами (`base.8a4bc8c52faa.css`) и
заголовком `Cache-Control: immutable`, а HTML — с `no-store`. Поэтому после
пересборки образа браузер получает актуальный CSS.

### Вариант 2: локально (venv)

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cd app
python manage.py migrate          # таблицы и три шаблона из фикстуры
python manage.py seed_demo        # демо-данные (необязательно)
python manage.py runserver
```

Откройте http://127.0.0.1:8000/ .

Тестовые учётные записи создаются командой `seed_demo`. Пароли задаются
переменными `DEMO_PASSWORD` и `ADMIN_PASSWORD`; если их не задать, для `demo`
будет сгенерирован случайный пароль и напечатан в логе, а администратор не
создаётся.

## Вход и регистрация

- **`/accounts/login/`** — вход по логину и паролю.
- **`/accounts/signup/`** — регистрация (логин, необязательный email, пароль и
  подтверждение). После создания аккаунта пользователь сразу авторизуется.
- **Вход через Google** — кнопка «Войти через Google» на страницах входа и
  регистрации. Показывается только при заданных ключах.

### Настройка входа через Google

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте
   **OAuth client ID** типа *Web application*.
2. В *Authorized redirect URIs* добавьте:
   `http://localhost:8000/accounts/google/login/callback/`
   (для прода — ваш домен).
3. Пропишите ключи в `.env`:

   ```bash
   GOOGLE_CLIENT_ID=…
   GOOGLE_CLIENT_SECRET=…
   ```

4. Перезапустите приложение: `docker compose up -d` или `runserver` локально.

При первом входе через Google аккаунт создаётся автоматически, логин
генерируется из email; при коллизии добавляется числовой суффикс.

## Тесты

```bash
cd app
python manage.py test builder
```

Покрыты регистрация, Google OAuth, доступ к проектам, версии и лимиты документа,
оптимистическая блокировка (`409`), публичная страница (`404`, CSP, `nosniff`,

| Модуль | Ответственность |

| `canvas.js` | холст, drag/resize, рамка выделения, пан, зум, drop |
| `render.js` | единый рендер элементов, секций, превью и экспорта |
| `panels.js` | правая панель свойств |
| `layers.js` | слои, группы и ассеты |
| `pages.js` | список и переименование страниц |
| `bundle.js` | многофайловый экспорт и сборка ZIP |

## Экспорт

Кнопка «Экспорт» собирает ZIP прямо в браузере:

```
index.html
another-page.html
assets/
  css/style.css
  js/main.js
  images/*
```

Каждая страница — отдельный HTML-файл, ссылки между страницами уже ведут на
файлы. CSS и JS общие, изображения вынесены в `assets/images`. ZIP собирается
собственным writer'ом, без внешних зависимостей.

При сохранении проекта дополнительно формируется автономный HTML для публичной
страницы `/p/<slug>/`: изображения встраиваются как data URI. Эта версия
открывается без сервера и используется в read-only превью.

### Как работает адаптивность

**Авторежим (по умолчанию):**

- каждая секция занимает всю ширину окна и красит фон во всю ширину;
- внутри секции лежит «канвас» шириной макета, который масштабируется
  коэффициентом `--sb-k = ширина_окна / ширина_макета`;
- на широких мониторах контент растёт до 1680 px и центрируется;
- **≤ 1023.98 px** — планшетный рефлоу: секции получают высоту по контенту,
  элементы выстраиваются в колонку, карточки сохраняют группировку;
- **≤ 767.98 px** — телефонный рефлоу: уже поля, компактнее типографика;
- горизонтальной прокрутки нет ни на 320 px, ни на 2560 px.

**Ручной режим:**

- при выключении «Авто» для каждой страницы создаются макеты планшета и
  смартфона;
- их можно править отдельно, не затрагивая десктоп;
- при экспорте рендерятся все три макета, нужный показывается через
  CSS-медиазапросы;
- если ручной макет ещё не создан, используется масштабированная десктопная
  версия (fallback).

## Заметки по разработке

- Шаблоны подгружаются автоматически сигналом `post_migrate` из фикстуры;
  повторный `loaddata` не требуется.
- `SECRET_KEY`, `DEBUG` и хосты настраиваются переменными окружения
  `DJANGO_SECRET_KEY`, `DJANGO_DEBUG`, `DJANGO_ALLOWED_HOSTS`.
- В `DEBUG` медиафайлы отдаёт Django; в проде их также обслуживает Django, а
  статику — WhiteNoise. Для полноценного продакшена медиа стоит вынести в nginx
  или объектное хранилище.
- Документ `Project.data` версионируется; старые версии автоматически
  поднимаются до v3 на клиенте.
- Для конкурентных правок используется оптимистическая блокировка по
  `updated_at`: при рассинхроне сервер отвечает `409`.
